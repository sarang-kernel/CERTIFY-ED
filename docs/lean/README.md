# lean

Lean 4 re-verification of CERTIFY-ED. The toolchain is Lean 4.35.0 (file `lean-toolchain`), the same build that was
used for the re-verification of the mm3x3 project, and Mathlib is the release `v4.35.0` (commit `56a005855ea1`), pinned
in `lake-manifest.json`.

## Libraries and programs

| Target | What it is | Imports Mathlib |
|---|---|---|
| `CertifyCore` | core-Lean library: exact rational arithmetic, IEEE-754 decoding, SHA-256, exact residual and inertia checks, kernel theorems about the finite arithmetic of the bounds | no |
| `cecheck` | compiled program (root `CertifyCore/Main.lean`) that re-checks certificate data exported from certify-ed | no |
| `CertifyMathlib` | formal proofs of the mathematical statements on Mathlib: `CertifyMathlib.Enclosure` (enclosures and the floating-point model), `CertifyMathlib.Counting` (counting, sector assembly, eigenspaces, observables), `CertifyMathlib.Apps` (the lemmas of the AKLT application) | yes |
| `CertifyApps` and `ceapps` | compiled recomputation of the certified application numbers (crown, AKLT, exact benchmarks) | no |

## Building on Windows

The Lean binaries are in `<lean-4.35.0-windows>\bin`
(no elan). Put that directory and `C:\Program Files\Git\cmd` on `PATH`, set `MATHLIB_CACHE_DIR` to
`lean\.mathlib_cache`, and run from this folder:

```
lake update                    # only once: fetches Mathlib v4.35.0 and its dependencies, then the prebuilt cache
lake exe cache get             # prebuilt Mathlib files from cache.mathlib.org (9031 files)
lake build                     # CertifyCore and CertifyMathlib
lake build CertifyApps cecheck ceapps
lake env lean Audit/AxiomAudit.lean    # axioms of every theorem of the three libraries
```

On this machine `curl` needed the option `ssl-no-revoke` (file `.curl/.curlrc`, selected with `CURL_HOME`), because the
certificate revocation server is not reachable from the build environment, and git needed `core.autocrlf=false` so that
the Mathlib sources keep the line endings that the cache hashes were computed from. A first elaboration of a file that
imports `Mathlib.Analysis.Matrix.Spectrum` took 249 s; later ones took 45 s with a peak of 1.55 GiB.

## Where the results are

`VERIFICATION_REPORT.md` is the report on the whole re-verification: every statement with its Lean names, its level
and what is not formalized, the certificate and application results, the second checkers, the axiom audit and the
findings for the documents. It is generated by `python ../tools/make_verification_report.py` from the files in
`results/`. The part documents give the full account of each part.

| Document | Part | Result files |
|---|---|---|
| `CORE.md` | `CertifyCore` and `cecheck`: the exact checker of certificates and the kernel theorems about the finite arithmetic | `results/core/` |
| `ENCLOSURE.md` | `CertifyMathlib.Enclosure` | `results/mathlib_enclosure.json` |
| `COUNTING.md` | `CertifyMathlib.Counting` | `results/mathlib_counting.json` |
| `APPS.md` | `CertifyApps`, `ceapps` and `CertifyMathlib.Apps` | `results/apps/` |
| `NONHERMITIAN.md` | `CertifyMathlib.NonHermitian`: Bauer-Fike and the residual forms of E-02 (11 November 2026) | `results/mathlib_nonhermitian.json` |
| `LEAN_PRODUCT.md` | `Verify/cecheck_bundle.py` and `CertifyMathlib.Refine`: the certificate driver and the refinement of the kernel checks (11 November 2026) | `results/lean_product.json` |
| `APPS_NEXT.md` | the applications N-11 and N-12, computed with the code of `dev/3.3`, without a Lean part (11 November 2026) | `results/apps_next/` |
| `VERIFICATION_REPORT.md` | the whole, with the integration checks | `results/integration.json`, `results/integration_logs/`, `results/findings_documents.json` |

The levels K, K2, K+, N, P and H are defined in the `README.md` of the repository. In short, K2 means that the Lean
kernel and the independent kernel nanoda accepted the theorem, and K+ that the Lean kernel accepted it and
`leanchecker` replayed its module. The folder `Verify/` holds the certificate driver of `LEAN_PRODUCT.md`. The folder `Audit/` holds the integration checks: `AxiomAudit.lean`,
`run_final_checks.py` (nanoda and the final `leanchecker` replay) and `make_integration_record.py`. The folder `Drafts/`
holds the axiom-printing files and nanoda drivers of the parts and is not part of any library; files named
`scratch_*.lean` are not tracked. `work/` and `logs/` are scratch folders and are not tracked.
