# docs/project/CHANGELOG_PROJECT.md: every recorded change of CERTIFY-ED, 18 December 2025 to 6 November 2026

This file lists, month by month, every change of the CERTIFY-ED project that a dated source of the project archive v5 records: code, mathematics, manuscripts, runs, decisions, applications, documents and archives, with the failures and reversals as well as the results. CERTIFY-ED (Sarang Vehale, with Ritu Goel) issues certificates for exact-diagonalization (ED) results. An ED result is a set of eigenvalues and eigenvectors that a program computed for a Hamiltonian matrix; a certificate states, statement by statement, what has been established about such a result for a declared model. The archive itself is described in `archive_v5/README_ARCHIVE.md`, and the consolidated report `archive_v5/report/CONSOLIDATED_REPORT.md` gives the technical detail behind every row.

## Terms used in the tables

The certificate statements are S1 model fidelity (the matrix is the declared model, checked against independent reference builders), S2 enclosures (an interval around each claimed eigenvalue that contains an eigenvalue of the declared model), S3 completeness (no eigenvalue is missing below a cut, shown by Sylvester inertia counts of a factorization), S4 eigenspaces (bounds on eigenvectors and observables), S5 corroboration by other solvers, S6 an exact re-check in rational arithmetic, S7 thermodynamic intervals and S8 degeneracy counts. Each statement ends with one of four statuses: CERTIFIED, FAILED, INCONCLUSIVE or NOT_CHECKED. The model shift is the bound on the difference between the producer's matrix and the declared model that is added to every radius. The experiments are E0 (verifier validation), E1 (failure matrix of planted errors), E2 (cost and memory), E3 (tightness), E4 (workflows W1 to W4), E5 (an ARPACK multiplet truncation), E6 (mutation analysis: small deliberate changes of the code that the test suite should detect; a mutant is killed when a test fails), E7 (exact benchmarks), E8 (comparison with symveig), E9 (the pyrochlore crown of Kránitz and Penc) and E10 (the AKLT criteria of Pomata and Wei). The computational source fingerprint (`source_hash`) is a hash of the code that can change a result; an evidence run is one full reproduction made from one tagged commit with no edits in flight (D-44). `compare_runs.py` compares two runs field by field and calls a field a MISMATCH when it differs outside every named class of expected differences (timings, digits that depend on the software stack, random samples, documented changes).

## Conventions

Each month opens with a paragraph on what changed and why, followed by a table with the columns Date, Area, Change and Source. Commit dates are author dates converted to India Standard Time (IST, UTC+05:30), the time zone of the project's records; run times are those of the machine that made the run, as its manifest writes them (UTC on the Linux machines, IST on the Windows workstation). Where a source gives only a month, the date says so. The area is one of code, mathematics, manuscript, runs, decisions, applications, documents and archive. Sources are paths relative to `archive_v5/`, commits of the code repository by their short id, and decisions by their id in `project_docs/DECISIONS_LOG.md`. The history of the code repository was rewritten on 21 October 2026 (D-48); every commit id here is a rewritten id, and ids quoted in documents written before that evening are old ids, mapped in `code/certify-ed/HASH_MAP.csv` and in the column `old_id` of `tools/changelog/commits.tsv`. Commits are grouped into one row per day and topic; every commit of every branch and tag is named in at least one row, and the complete list with dates and subjects is `tools/changelog/commits.tsv`.

Under the project's rule D-12, new mathematics counts as established only after Sarang Vehale has re-derived it. The 22 derivation documents of `code/certify-ed/docs/proofs/` are therefore described as derived, machine-checked and independently re-derived (a second derivation written from the statement alone, not a human check), with Sarang's check pending; "certified" means certified by the implementation, subject to those pending checks. Manuscript prose is Sarang's (D-16), and the cited version of the code is still 3.1.0 until he decides otherwise (D-61).

## Regenerating this file

```
python tools/changelog/collect.py
python tools/changelog/build.py
python tools/lint_docs.py docs/project/CHANGELOG_PROJECT.md
python tools/lint_docs.py --bundle tools/changelog/changelog_sources_bundle.txt docs/project/CHANGELOG_PROJECT.md
```

`collect.py` reads the clone `archive_v5/code/certify-ed` with git and writes the tables `commits.tsv`, `tags.tsv`, `decisions.tsv` and `runs.tsv`; `build.py` assembles this file from `entries.tsv`, `months.tsv`, `versions.tsv` and `intro.md` and checks that every row has a source that exists and that every commit, decision, run record and handover is cited; the second lint call also checks that every number of three or more digits occurs in a cited source.

## May 2026

May 2026 produced v1 and a research programme around it. A first package and manuscript of 5 May drew a critical review (known results presented as theorems, illustrative instead of measured figures, no code), so the package was rebuilt the next day and released as v1.0.0 on 7 May, with a benchmark run behind its numbers; it was posted to arXiv and submitted to SciPost Physics Codebases. Two research directions were piloted before any theorem was attempted, so that a weak direction would be stopped cheaply: C2, sector-decomposed enclosures with guaranteed error bounds, was killed because the literature already covered it and the pilot gain was 5.2 to 5.5 times against a pre-registered 100 times; C1, Chebyshev-preconditioned Krawczyk verification, passed its pilot on two stacks and exposed an overflow bug on the way. symveig 1.0.0, the implementation work that survived C2, was released on 22 May.

## October 2026

October 2026 holds most of the recorded changes. The v2 core gained the experiments E0 to E5 and the manuscript ms_v2 (4 to 11 October), and the experiments found bugs of the code itself (the Jordan-Wigner direction, unseeded ARPACK, the below-top probe). After SciPost was dropped on 15 October and a survey of horizons showed that published proofs rest on uncertified ED numbers, the project turned to certifying such proof lemmas (the pyrochlore crown of Kránitz and Penc and the AKLT criteria of Pomata and Wei), added an exact re-check layer and mutation analysis, merged symveig after an audit found its counts unproved, and became one codebase, certify-ed 3.0.0 (17 to 18 October). Writing the appendix proofs against the code on 21 October found two soundness gaps, fixed before the full run; an automated independent review that evening found three input paths that gave a false CERTIFIED and the private address in the history, which led to the history rewrite and to release 3.1.0. The first attempt of the 3.1.0 evidence run failed on Windows-portability defects; the second, from tag `v3.1.0`, is the run the paper cites, and the four known issues found afterwards were recorded instead of rerunning it (D-57). From 23 October a scored expansion roadmap drove Waves 0 and 1 on `dev/3.2`, and from 30 October a completion plan cleared the backlog of new mathematics with derivation documents, machine checks and an independent re-derivation, while Sarang's own check stays pending (D-59).
